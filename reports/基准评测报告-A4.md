## 0. 一页纸结论

| 场景（初值误差 / 电流偏置） | 库仑计数 | EKF | UKF | AEKF |
|---|---|---|---|---|
| `known`　0 pp / 0 A | **0.01** | 2.62 | – | – |
| `bias20ma`　0 pp / +20 mA | **0.90** | 1.93 | 3.31 | 1.63 |
| `init30`　−30 pp / 0 A | 28.68 | 3.31 | 3.81 | **3.11** |
| `hard`　−30 pp / +20 mA | 27.86 | 2.88 | 3.21 | **1.72** |

*表：24 段动态工况、留一工况参数、全程 RMSE 中位数（单位：百分点 pp，1 pp = 1% SOC）。*

四条结论：

1. **模型误差是地板，滤波器不是。** 在初值完全已知、电流完全准确的 `known` 场景里，
   EKF 仍有 2.62 pp；这不是收敛慢，是二阶 RC + 静态 OCV 表本身对不上
   （留一工况开环电压残差中位数 52.6 mV）。库仑计数在同场景是 0.01 pp——因为它
   根本不看模型。**滤波器能做的只是「别让模型误差变成 SOC 误差」，不能消灭它。**
2. **滤波器的价值全部来自「初值未知」这一件事。** 初值偏 −30 pp 时，库仑计数 28.68 pp、
   EKF 3.31 pp，差 8.7 倍；但电流偏置只有 20 mA 时，库仑计数 0.90 pp 反而**优于**
   EKF 的 1.93 pp。结论很直接：**如果电流传感器够准，纯积分很难被打败**；
   上滤波器的理由是「上电时 SOC 未知」和「偏置更大」，而不是「提高稳态精度」。
3. **AEKF 在「两个误差叠加」时优势最大**：`hard` 场景 1.72 pp（EKF 2.88、UKF 3.21），
   92% 的工况 60 s 内收敛到 5 pp 以内（EKF 50%、UKF 21%）。但在 `init30`（无偏置）上
   它与 EKF 只差 0.2 pp（3.11 vs 3.31）——**自适应量测噪声主要治的是偏置，不是初值**。
4. **UKF 没有系统性优势**，三个能比的场景里**每一个**都比 EKF 差
   （`hard` 3.21 vs 2.88、`bias20ma` 3.31 vs 1.93、`init30` 3.81 vs 3.31）。
   这里要说清楚：一开始 UKF 错到 **59 pp**，那确实是一个**实现 bug** —— OCV 表在 SOC 边界外
   被 `np.clip` 夹成常数，sigma 点越界后无迹变换的均值被系统性拉偏（§8.2）。
   修完后 UKF 回到 2–3 pp 量级，**剩下的差距**才是「UKF 在这类 `h` 上的固有代价」。
   工程结论：为了「不用求导」付这个代价不值得 —— EKF 的雅可比是解析的、只花 4 个浮点运算。

## 1. 任务与交付物

清单 A4 的原始要求是「EKF/UKF/AEKF 三版估计器对比 + 动态工况 RMSE 精度评估 +
可复用的估计器代码模块」，并注明**与已完成的 ECM 参数辨识项目是上下游关系而非重复** ——
辨识出的参数正是本项目的模型输入。

本项目的交付物：

| 交付物 | 位置 | 说明 |
|---|---|---|
| 可复用估计器模块 | `src/bmsoc/filters.py` | `CoulombCounter / EKF / UKF / AEKF`，统一 `run()` 接口，见 §10 |
| 等效电路与辨识 | `src/bmsoc/ecm.py` | 二阶 RC、变量投影 + NNLS、整段工况拟合 |
| OCV 建模 | `src/bmsoc/ocv.py` | PAVA 保序 + PCHIP + 二维 `OCV(SOC,T)` 表 |
| 数据层 | `src/bmsoc/io_*.py`, `profiles.py` | Panasonic / CALCE 读取、重采样、真值 SOC |
| 指标 | `src/bmsoc/metrics.py` | RMSE / 尾段 RMSE / 收敛时间 / 超限占比 |
| 流水线 | `scripts/00–08` | 勘察 → 辨识 → 留一标定 → 基准 → 敏感性 → 出图 → 两个诊断 |
| 单元测试 | `tests/`（59 项） | 全部用合成数据，不依赖数据集 |

### 与 ECM 参数辨识（`锂电池ECM-RUL-统一项目`）的分工

那边的产物是「ECM 参数辨识」，本项目把它当输入：

```
HPPC 脉冲 ──► OCV(SOC,T) ─┐
                          ├──► 二阶 RC 参数表 ──► 留一工况标定 ──► 三个滤波器 ──► SOC
动态工况电压/电流 ─────────┘   （ECM-RUL 项目的方法）  （本项目）        （本项目）
```

OCV 用 HPPC 静置点（物理干净）；电气参数（R0/R1/τ1/R2/τ2）在动态工况上留一标定
（因为 HPPC 的 10 s 脉冲外推到半小时工况会系统性放大慢极化支路，见 §5.3）。

## 2. 数据

### 2.1 规模

**Panasonic NCR18650PF（主数据集）**

| 项 | 数量 | 说明 |
|---|---|---|
| 单工况动态文件 | 25 | −20/−10/0/10/25 °C × US06/UDDS/LA92/NN/HWFET 的不完整组合 |
| 进入基准 | **24** | −20 °C 有两个 US06（其中一个含升温段），去重 |
| HPPC 五脉冲文件 | 5 | 每温度一个，用于 OCV 与 RC 参数 |
| 原始采样 | 0.1 s | 静置段 60 s |
| 单段时长 | 44–410 min | 含开头 0–2 h 温箱静置 |

**CALCE A123（用于跨数据集勘察，未进入主基准，见 §11）**：8 个 OCV 包 + 8 个 DST/US06/FUDS 包，
Arbin `.xlsx`，`Channel_1-006` 表。

### 2.2 容量基准必须同源

真值 SOC 定义为 `soc_ref = 1 + ∫I dt / Q_ref`。`Q_ref` 一律取 **HPPC 一次完整放电的电量**：

| 温度 | 25 °C | 10 °C | 0 °C | −10 °C | −20 °C |
|---|---|---|---|---|---|
| `Q_ref` (Ah) | 2.773 | 2.622 | 2.476 | 2.330 | 2.182 |

这是踩过的坑：早期版本 OCV 的 SOC 轴用 HPPC 容量、动态工况的真值用各自一次测试放出的电量
（25 °C 是 2.586 Ah），两者差 7%，模型电压立刻出现 133 mV 的系统性偏差——看起来像
「模型不准」，实际是两个 SOC 轴不一致。统一后同一个模型的开环残差降到 36–96 mV。

### 2.3 坑一：重采样把 55% 的样本电压填错了

这是本项目**最大的一个 bug**，它导致低温全线指标崩坏，值得单独写。

原始文件重采样到 1 s 时，`resample()` 需要给「没有原始采样点的区间」填值。早期实现是：

```python
arr[bad] = arr[good[0]] if good[0] > 0 else arr[good].mean()
```

`good[0] == 0` 几乎总是成立（第一个区间就有效），于是走 `else` 分支——
**所有空区间被填成整段电压的均值**。

而这批文件的低温工况开头有 2 h 温箱静置、采样间隔 60 s：

| 工况 | 空区间占比 | 工况 | 空区间占比 |
|---|---|---|---|
| −20 °C LA92 | 54.7% | −10 °C US06 | 68.5% |
| −20 °C NN | 60.2% | 0 °C NN | 52.2% |
| −20 °C HWFET | 61.8% | 25 °C 全系列 | 0.1% |

于是 −20 °C LA92 的 12850 个样本里有 7080 个的电压是 3.47 V（真值 4.17 V）——
滤波器当然会崩：EKF 全程 RMSE **86.9 pp**，AEKF 84.0 pp。

改成**前值保持**（零阶保持，与「BMS 按 1 s 采样 60 s 变一次的模拟量」语义一致）后，
静置段电压恢复为 4.1808 → 4.1711 V（随降温松弛 10 mV），同一工况 EKF 降到 **1.77 pp**。

修复后全量重跑，`known` 场景 EKF 从 7.05 pp 降到 **2.62 pp**——
**之前那个「解释不清的 7 pp 地板，有四分之三是这个 bug**。

### 2.4 坑二：标称温度不是实测温度

多数工况是「边降温边跑」：

| 文件标称 | 实测电芯温度范围 |
|---|---|
| 10 °C 组 | 23.7 → 12 °C |
| −20 °C 组 | 16.1 → −16.3 °C |

若整段当一个温度，OCV 会错几十毫伏，而滤波器会把它算成 SOC 误差。所以 OCV 做成
`OCV(SOC, T)` 二维表、按**实测电芯温度**逐样本查表（BMS 本来就有温度，这个做法是可部署的）。

### 2.5 坑三：开头两小时静置会把指标稀释

修好 §2.3 之后，静置段（电流 0、电压恒定）占样本数的 55%，RMSE 会被这种「什么都不发生」
的样本拉低。本项目把每段开头的长静置**裁剪到 300 s**：

- 评估目标明确为「动态工况精度」；
- 保留 300 s 是为了让滤波器有真实的上电收敛窗口（BMS 上电到起步之间就是这么一段）。

裁剪后 −20 °C LA92 从 12850 样本变 6008 样本，其余工况基本不变（25 °C 系列没有长静置）。

## 3. 模型

### 3.1 二阶 RC（Thevenin 双极化）+ 偏差状态

状态 `x = [soc, u1, u2, b]`，电流符号约定为**充电为正、放电为负**：

```
soc[k+1] = soc[k] + η·i[k]·Δt / (3600·Q)
u_j[k+1] = e_j·u_j[k] + R_j(1−e_j)·i[k],      e_j = exp(−Δt/τ_j)
V[k]     = OCV(soc[k], T[k]) + u1[k] + u2[k] + R0·i[k] + dv + b[k]
```

`u1/τ1` 是秒级电化学极化，`u2/τ2` 是分钟级浓差极化，`dv` 是标定得到的 OCV 基准偏移，
`b` 是在线估计的电压偏置状态。

### 3.2 为什么必须有第 4 个状态 `b`

只有三个状态时，任何**持续**的模型偏差（本数据集上 20–50 mV）在稳态都会被解释成
「SOC 错了」，滤波器于是停在一个 4–5 pp 的平台上——这是实测出来的地板，不是收敛慢。

把偏差显式建成状态、给它很小的过程噪声（`q_b = 1e-12`），新息里的常值部分就落到 `b` 上，
SOC 得以保持库仑计数的短期精度。效果：

| 配置 | `known` 场景 EKF 全程 RMSE |
|---|---|
| 3 状态 `[soc,u1,u2]` | 3.87 pp |
| 4 状态 `[soc,u1,u2,b]` | **2.15 pp**（当时数据，未修 §2.3 的 bug） |

图 `docs/figures/bias_state.png` 展示 −20 °C LA92（初值 −30 pp、偏置 +20 mA）上 `b` 的收敛过程，
但这里的细节比「b 收敛到 −dv」更有意思：

| | `b` 稳态值 | `σ_SOC` 稳态 | 说明 |
|---|---|---|---|
| 标定值 −dv | **+137.8 mV** | – | 折参数给出的 OCV 基准偏移 |
| EKF | **+162.8 mV** | 0.20 pp | 比 −dv 多出的 ~25 mV 是 20 mA 偏置 + 残余模型误差 |
| AEKF | **+67.9 mV** | 0.31 pp | 只吸收了不到一半 |

**AEKF 的 `b` 停在 +68 mV 而不是 +138 mV，不是没收敛，是分工变了**：它把 `R` 抬高之后，
一部分「模型不可信」的信息被 `R` 吃掉了，不需要全部压给 `b`。同一个物理偏差，
在两个滤波器里被拆到两个不同的地方 —— 这也是 §9.3 里 AEKF 在高噪声下反而更好的同一条机制。

⚠️ **`b` 不是免费的**：它与 SOC 在「OCV 平台区」上不可分辨（见 §7）。给它太小的
过程噪声会让它跟不上真实的时变偏差，太大则会和 SOC 抢同一个新息。

## 4. 三个滤波器

差别只在「怎么传播协方差」与「是否在线调噪声」，预测/量测方程完全一致。

| | 协方差传播 | 雅可比 | 在线调参 |
|---|---|---|---|
| EKF | `P⁺ = (I−KH)P(I−KH)ᵀ + RKKᵀ`（Joseph） | 解析 `H=[dOCV/dSOC,1,1,1]` | 无 |
| UKF | 2n+1 = 9 个 sigma 点，对称采样 | 不需要 | 无 |
| AEKF | 同 EKF | 同 EKF | 滑动窗（60 s）新息协方差匹配，**只调 R** |

三个实现细节：

1. **`_init_state` 用稳态极化 `R_j·i0`**，而不是 0。工况开头电流通常非零，
   若初始极化置 0，前几分钟会出现一个假瞬态（实测把 `known` 场景推高约 1 pp）。
2. **AEKF 只自适应 `R`**。早期版本同时自适应 `Q_soc`，在 NN 工况上把 `Q_soc` 放大到
   发散（29 pp）——SOC 的过程噪声一旦被放大，滤波器就退化成「相信电压、不信积分」，
   而电压恰恰是最不可靠的那一路。
3. **UKF 用 `alpha=1.0`**。`alpha=0.3` 时 `λ = α²(n+κ) − n < 0`，负权重把协方差压坏
   （实测 45 pp）；改用 `alpha=1.0` + 特征值截断的 PSD 投影。

## 5. 参数辨识

### 5.1 OCV：HPPC 静置点 → PAVA → 平滑 → PCHIP

对每个 HPPC 文件，取「脉冲前的一段静置」的末电压作为该 SOC 的 OCV。
25 °C 得到 66 个点、13 个 SOC 档。原始点并不严格单调（测量噪声），用 **PAVA 保序回归**
强制单调，25 °C 的最大改动量 1.29 mV——说明静置法本身质量不错。

但直接插值会踩一个坑：**每个 SOC 档的 5 个脉冲给出 5 个几乎同 SOC 的点**
（档内 SOC 跨度约 0.005），它们的静置末电压差只有 0.6–8 mV——这是重复测量，不是真实斜率。
−20 °C 更极端：35 个点里 **25 对相邻点的电压完全相同**（记录分辨率 0.1 mV，
低温下 20 min 静置几乎不松弛），PAVA 之后整段变成阶梯。

PCHIP 穿过阶梯后，`dOCV/dSOC` 在 **0.00 与 2.91 之间乱跳**（25 °C 实测）——
阶梯之间是平的（斜率≈0），阶梯上是陡的。而滤波器正是用这个斜率算卡尔曼增益的：
斜率 0 意味着「电压对 SOC 完全不敏感」，增益为 0，滤波器在那儿会彻底停更。

修法：先用平滑样条（残差目标 1.5 mV，与记录精度同量级）在 SOC 方向重建曲线，
PAVA 保序，再做一次窗口平均（单调序列的平均仍单调，但阶梯会变成斜坡）。效果
（SOC ∈ [0.02, 0.98]、201 点等距网格，`scripts/08_ocv_slope_check.py` 可复现）：

| | 25 °C | −20 °C |
|---|---|---|
| 平滑前 `dOCV/dSOC` 范围 | 0.00 – 2.91 | 0.00 – 2.09 |
| 平滑后 | **0.43 – 2.95** | **0.26 – 2.47** |
| 平滑前 中位/最小 | 1.0×10⁵ | 9.9×10⁴ |
| 平滑后 中位/最小 | **2.1** | **2.5** |
| 平滑后 相邻点最大比值 | 1.2 | 1.2 |

五个温度**全部**满足「平滑后最小斜率 ≥ 0.26」且「相邻点最大比值 ≤ 1.25」：
最小斜率 0.26 / 0.35 / 0.47 / 0.47 / 0.43，中位/最小 2.5 / 2.0 / 1.7 / 1.8 / 2.1
（−20 / −10 / 0 / 10 / 25 °C），也就是说斜率不再有 0 这种病态点。
拟合残差 1.50 mV（五个温度全部落在目标上），单调性违规从 1.29–2.15 mV 降到 0。
留一工况验证残差中位数不变（52.6 mV），说明平滑去的是伪影而不是信号。

图 1b 就是这个斜率的形状：五个温度的 `dOCV/dSOC` 在 **0.26–1.25 V/unit** 之间起伏，
最平的谷出现在 −20 °C 的 SOC≈0.59（0.26）和 25 °C 的 SOC≈0.35（0.43）。
**谷底不是噪声而是真实的拐点** —— 用 0.01 宽的中心差分和用 1e-4 的局部斜率给出同一条曲线
（`scripts/06_figures.py` 与 `OCV2D.docv` 互相验证）。工程含义很直接：
同样 10 mV 的电压误差，在谷底折算成 0.8 pp SOC，在 SOC→0 的陡坡上只折算成 0.2 pp ——
**同一个滤波器在不同 SOC 区间的增益差 4 倍是正常的，不是 bug。**

### 5.2 RC 参数：单脉冲不可辨识，必须多倍率联合

HPPC 每个 SOC 档有 1C/2C/4C/8C/12C 五个 10 s 脉冲。早期版本对单个脉冲做 5 参数非线性最小二乘，
结果不可辨识：`τ2` 顶到上界 5000 s，`τ1` 在 5–67 s 之间乱跳。

改为**变量投影**：`τ1/τ2` 走格点（`TAU1_GRID` 2–60 s 九个点，`TAU2_GRID` 80–2000 s 九个点），
给定 `τ` 后模型对 `[R0, R1, R2]` 是线性的，用 NNLS 解，再对格点取最优；
并且把**同一 SOC 档的 5 个倍率脉冲联合**堆叠成一个最小二乘问题（`identify_stack`）。
不同倍率给出不同的极化深度，联立后才能把两条时间常数分开。

分档判据也踩过坑：最初想用「两次脉冲之间是否有 ≥60 s 的 1C 放电」判断档间边界，
但 HPPC 的档间放电是紧接 17.4 A 脉冲的 1.45 A 慢放，判据失效；最终用
「相对本档首个脉冲 SOC 降幅 > 3.5%」分档（档内实测 2.2%，档间 5.2%）。

结果（各 SOC 档的中位数）：

| 温度 | 25 °C | 10 °C | 0 °C | −10 °C | −20 °C |
|---|---|---|---|---|---|
| `R0` (mΩ) | 30.6 | 41.1 | 52.9 | 73.0 | 103.2 |
| `R1` (mΩ) | 5.1 | 6.8 | 14.5 | 36.3 | 72.7 |
| `τ1` (s) | 12 | 8 | 5 | 3 | 5 |
| `R2` (mΩ) | 60.6 | 55.7 | 62.6 | 84.7 | 110.1 |
| `τ2` (s) | 2000 | 1100 | 900 | 600 | 600 |
| 单档拟合 RMSE | 8.7 mV | 11.9 mV | 19.3 mV | 23.5 mV | 22.6 mV |

`R0` 从 25 °C 到 −20 °C 涨 **3.4 倍**，与 Arrhenius 行为的量级一致。低温下不只是 `R0` 涨，
**`R1`（秒级极化）涨得更凶**（5.1 → 72.7 mΩ，14 倍），`τ1` 同时从 12 s 缩到 3–5 s ——
这说明低温的极化是「快而大」，与常温的「慢而小」不是同一个物理过程，
用单一温度参数外推必然出错（这也是 §5.3 要重标定的原因）。

### 5.3 电气参数：在动态工况上留一标定

HPPC 只有 10 s 脉冲，外推到半小时工况时慢极化支路会被系统性放大
（早期实测开环电压偏置 −30 ~ −70 mV，US06 低 SOC 处到 −128 mV）。

于是：**OCV 固定为 HPPC 静置曲线，6 个电气参数（R0 三节点 + R1/τ1 + R2/τ2 + dv）
在每个温度的动态工况上拟合，并轮留一条工况做验证**。用 `lfilter` 做 RC 递推（比逐点循环快 50 倍）。

关于 `dv`：它是「HPPC 静置 OCV」与「动态工况实际 OCV 基准」之间的系统差，必须显式建出来，
否则这条 100 mV 级的常值偏差会被 `R` 或 SOC 去吸收。它的取值本身就是诊断信号：
**24 折里 0 折顶到 −150 mV 边界**（旧版有 5 折顶死），最负的一折 −138 mV 出现在 −20 °C，
最正的 +13 mV 出现在 10 °C。低温 `dv` 系统性为负、幅度随温度单调增大，
说明**低温的 OCV 表与动态工况的基准存在结构性偏差**（见 §11）。

结果（24 折，验证集 = 被留出的那条工况）：

| 温度 | 验证 RMSE 范围 | 中位数 | 最差工况 |
|---|---|---|---|
| 25 °C | 17.3 – 48.7 mV | 27.5 mV | US06 48.7 |
| 10 °C | 29.1 – 74.1 mV | 40.7 mV | US06 74.1 |
| 0 °C | 28.5 – 81.8 mV | 40.2 mV | US06 81.8 |
| −10 °C | 39.8 – 111.6 mV | 59.1 mV | US06 111.6 |
| −20 °C | 77.9 – 196.8 mV | 98.6 mV | US06 196.8 |

全体中位数 **52.6 mV**，P90 **99.8 mV**。**五个温度的最差折全是 US06**
（48.7 / 74.1 / 81.8 / 111.6 / 196.8），因为它是电流最激烈的工况，`R0` 的误差被放得最大。

`τ2` 在 24 折里有 **17 折**顶到 6000 s 上界（旧版 20 折）——这说明**二阶 RC 的慢支路在数小时的工况上
退化成一个准稳态漂移项**，而不是一个真正的极化时间常数。这是模型结构的局限，不是拟合没做好。

## 6. 评测协议

### 6.1 为什么不测「初值已知 + 电流完美」

那样库仑计数会精确复现真值（真值本来就是同一路电流对同一容量积分），滤波器只会往里加噪声，
基准变成循环论证。真实 BMS 的痛点有两个：

1. **上电时 SOC 未知**；
2. **电流传感器有偏置**（20 mA ≈ 0.7% C，积分一小时就是 0.02 Ah 漂移）。

于是四个场景（`SCENARIOS`）：

| 场景 | 初值误差 | 电流偏置 | 用来回答 |
|---|---|---|---|
| `known` | 0 | 0 | 模型误差的地板有多高 |
| `init30` | −30 pp | 0 | 电压反馈能不能把初值拉回来 |
| `bias20ma` | 0 | +0.02 A | 小偏置下滤波器是否值得 |
| `hard` | −30 pp | +0.02 A | 两个误差叠加 |

**真值始终由原始电流积分**（不掺假），`current_bias_a` 只影响估计器看到的电流。
这一点很关键：否则「估计器 vs 真值」同源，库仑计数会得到 0.01 pp 的假精度。

### 6.2 初值协方差

`init30` 场景给 `sigma_soc0 = 0.20`（真值是 0.30 的误差，给 0.20 是保守但合理的先验）；
`known` / `bias20ma` 给 0.05。这个设置直接影响了 UKF 的表现（§8），所以必须写清楚。

### 6.3 指标

- `rmse`：全程 RMSE；
- `tail_rmse`：末 30% 的 RMSE（稳态精度）；
- `converge5_s`：**首次进入并一直保持在** 5 pp 以内的时间（末尾出带即判未收敛，返回 NaN）；
- `frac_out_2pp`：超出 2 pp 的样本占比。

读法：

1. **一旦初值错了 30 pp，纯积分就废了**（27–29 pp），而三个滤波器都在 4 pp 以内 ——
   这就是「用电压回拉积分」的价值。
2. **AEKF 在三个多估计器场景里全程 RMSE 全部最低**，且 `hard` 场景优势最大（1.72 vs 2.88 / 3.21）。
   P90 差距更明显：`hard` 3.30 vs 6.69，`bias20ma` 5.19 vs 8.99。
3. **但 AEKF 在 `init30` 上只比 EKF 好 0.2 pp**（3.11 vs 3.31）。自适应量测噪声治的是
   **持续偏置**（`R` 变大 → 少信电压 → 靠积分平滑），不是**初值误差**（需要小 `R` 快速吸收
   第一波新息，两者方向相反）。证据：`init30` 里 AEKF 的中位收敛时间与 EKF 相同（都是 1 s），
   但 60 s 内收敛占比只从 0.46 提到 0.58 —— 它要么一开始就对，要么长期进不了带内，
   而 `hard`（同样 −30 pp 初值、**外加** 20 mA 偏置）的占比直接跳到 0.92。**偏置才是 AEKF 的靶子。**
4. **UKF 四个场景每一个都比 EKF 差**，而且 `60 s 内收敛占比` 是 EKF 的一半到四分之一
   （0.12 vs 0.25 / 0.21 vs 0.50）。原因见 §8 —— 这不是「UKF 不行」，是**这套 OCV 表的边界形状**
   恰好是 EKF 的舒适区。
5. `bias20ma` 是唯一库仑计数赢的场景（0.90 pp）。见 §7.3。

两个观察：

1. **温度对精度的影响不是单调的，10 °C 最差**（`hard` 场景 EKF 4.06 pp，比 −20 °C 的 1.76 还差）。
   翻到逐工况明细就清楚了：10 °C 的 5 条工况**全部**落在 3.4–4.3 pp（唯一的 17.7 来自 US06 这条短工况），
   没有一条是好的 —— 这是**系统性**的折参数偏差，不是离群点。原因指回 §2.4：标称 10 °C 的文件
   实测温度从 23.7 °C 一路降到 12 °C，是温度跨度最大的一组，而折参数是**单温度**拟合的，
   在整段上的等效误差最大。OCV 斜率这条路走不通 —— 各温度的最小斜率都在 0.43–0.47 V/单位 SOC
   之间，差不到 10%，解释不了 2.3 倍的精度差。
2. **AEKF 的收益在低温最明显**（`init30`：−20 °C 1.00 vs EKF 2.58、−10 °C 0.57 vs 3.04），
   因为低温下 `R` 的真实值（电压噪声 + 模型偏差）远大于标称的 `σ_v = 10 mV`，
   固定 `R` 的 EKF 被「假精度」拖累，AEKF 自己把 `R` 抬上去就对了。

**「低温反而更容易」只在 `known` 场景成立**（−20 °C 开环残差最大但 `dOCV/dSOC` 也最大），
一旦叠加 20 mA 偏置和 30 pp 初值误差，低温的优势就被抵消了 ——
**精度不取决于模型准不准，而取决于「模型误差 ÷ OCV 斜率」这个比值**。

### 7.3 库仑计数为什么在 `bias20ma` 里赢

`bias20ma` 的偏置是 0.02 A，纯积分就是一个线性斜坡，端点漂移 = `0.02 A × 时长 / 容量`。
RMSE 是整个斜坡的均方根，所以约等于端点的 `1/√3`：

| 工况 | 时长 | 端点电量误差 | 端点 SOC 漂移 | 实测 `cc` RMSE |
|---|---|---|---|---|
| −20 °C US06 | 44 min | 0.015 Ah | 0.7 pp | 0.40 |
| 25 °C US06 | 80 min | 0.027 Ah | 0.96 pp | 0.57 |
| −20 °C LA92 | 100 min | 0.033 Ah | 1.5 pp | 0.89 |
| 25 °C LA92 | 235 min | 0.078 Ah | 2.8 pp | 1.63 |
| 10 °C UDDS | 356 min | 0.119 Ah | 4.5 pp | **2.62** |
| 25 °C UDDS | 374 min | 0.125 Ah | 4.5 pp | **2.60** |

*容量：−20 °C 2.182 Ah，25 °C 2.773 Ah（§2.2）。*

中位数 0.90 pp，而 EKF 要付 1.93 pp 的模型误差。**这条数据集上的电流传感器质量很高**
（倍率精度优于 0.5%），所以小偏置下纯积分确实更优。这不是「EKF 不行」，
而是「**EKF 在电流可信时，是在用不可信的电压去修正可信的积分**」。

但库仑计数的命门也在这张表里：它是**无界**的。EKF 的 1.93 pp 不随时长增长
（它每个采样都在被电压拉一把），而 cc 的误差和时长**严格成正比** ——
UDDS 那条 6 小时工况已经到 2.6 pp，再长一倍就翻倍。
§9.2 的敏感性扫描给出了偏置轴上的拐点：到 ±50 mA 时 cc（2.63）才与 EKF（3.46）持平，
**在此之前纯积分一直更优** —— 这个拐点比直觉的 ±20 mA 远得多。

## 8. UKF 为什么没有优势：两个坑

这一节是本次投入最多的地方，因为 UKF 一开始的结果是**明显错的**（同一批工况 17–62 pp，
见 §8.2 的 A/B 表），而不是「略差」。定位过程有两个发现：一个是权重不一致（真但次要），
一个是 OCV 表的边界行为（真正的主因）。

### 8.1 坑一：`wm[0] = 0` 而 `wc[0] = β = 2`

`alpha=1, kappa=0, n=4` 时 `λ = 1²(4+0) − 4 = 0`，于是

```
wm[0] = λ/(n+λ) = 0
wc[0] = λ/(n+λ) + (1 − α² + β) = 2
```

中心 sigma 点在**均值**里权重 0、在**协方差**里权重 2。对线性量测这没影响
（中心点的偏差 `dY[0] = 0`，见 §8.1 末尾的单元测试），但对非线性量测，
`dY[0] = E[h] − h(μ)` 正是无迹变换的均值偏差，它会被 `wc[0]=2` **平方**后加进 `S`：

| SOC | σ=0.05 | σ=0.10 | σ=0.20 | σ=0.30 |
|---|---|---|---|---|
| 0.30 | −0.8 mV | −3.4 | −9.4 | −18.1 |
| 0.50 | +1.4 | +4.7 | +9.4 | +10.8 |
| 0.90 | −1.1 | +0.7 | **+13.5** | **+26.5** |

*表：25 °C OCV 表（线性外推版）上，标准 9 点 UT 的 `E[OCV] − OCV(μ)`。*

最大 27 mV，`2×0.027² = 1.5e-3`，而 `R = σ_v² = 1e-4` —— `S` 被抬约 **15 倍**，增益被压掉一个量级。
这足以让 UKF 变慢、变钝，但**不足以**造成 60 pp 的错误。所以这一项要修，
但它不是本项目 UKF 失效的原因（原因在 §8.2）。

把同一网格换成**夹紧**版 OCV，`SOC = 0.90` 那一行变成 **−1.1 / +0.7 / −9.8 / −20.1** ——
**符号翻转了**。这不是 β 的问题，是 `h` 被改坏了。

把 `β` 设为 0（使 `wc ≡ wm`）可以消掉这一项，效果**一半有用一半没用**：

| 工况 | 夹紧 `β=2` | 夹紧 `β=0` | 外推 `β=2` | 外推 `β=0` |
|---|---|---|---|---|
| −20 °C NN `known` | 58.97 | 59.93 | 2.19 | **1.28** |
| −20 °C NN `init30` | 62.21 | **35.76** | 2.56 | 2.66 |
| −20 °C LA92 `bias20ma` | 40.18 | 29.75 | 6.94 | 6.92 |
| 0 °C NN `known` | 17.28 | 18.40 | 6.01 | 5.90 |

*全程 RMSE，pp。同一 OCV 表、同一折参数、同一噪声种子（`scripts/07_ukf_clip_ab.py`）。*

`β=0` 能把 `init30` 的 62 pp 砍到 36 pp（因为初值差 30 pp 时 σ 大、sigma 点跨度大，
UT 偏差最大），但**改不动 `known` 场景**，而且 40 pp / 36 pp 仍然是完全不可用的量级。
**所以 β 不是主因**，但它确实是一个值得写清楚的机制：

- 对**线性**量测 `dY[0] = E[h] − h(μ) = 0`，`β` 完全不起作用 ——
  单元测试 `test_ukf_equals_ekf_for_linear_measurement` 用的就是默认 `β=2`，与 EKF 在 `1e-4` 内重合；
- 对**非线性**量测 `dY[0] ≠ 0`，`β=2` 把这个偏差**平方**后灌进 `S`，σ 越大错得越多；
- 本项目最终**保留 `β=2`**（标准取值）。外推修好之后两列只差 0.1–0.9 pp，
  而 `β=0` 在 `init30` 上反而略差（2.66 vs 2.56）。**保留默认值 + 修边界**比调参更干净，
  也不会让「UKF 比 EKF 差」这个结论背上「我们偷偷调过参」的嫌疑。

### 8.2 坑二（真正的主因）：OCV 表在 SOC 边界外被夹紧

追踪 −20 °C NN `known`（真值 SOC 1.00 → 0.20）可以看到两个版本的差别：

| 版本 | `soc_hat` 最大 | 最小 | 触上界(1.05)样本 | 触下界(−0.05)样本 | 前 600 s 新息均值 |
|---|---|---|---|---|---|
| 夹紧 | 1.050 | **−0.050** | 305（6%） | **2796（58%）** | **+3.2 mV** |
| 外推 | 1.050 | 0.181 | 3（0.06%） | 0 | −2.2 mV |

夹紧版最后 **58% 的时间贴在 −0.05 的下限上**（真值降到 0.20），而外推版全程没离开过 0.18 以上。机制是一条「离开真值的棘轮」：

1. SOC 接近 1.0 时，一半 sigma 点越上界，夹紧使 `E[OCV] < OCV(μ)` → 预测端电压偏低
   → 新息为正 → 滤波器把 SOC 继续往上推 → 撞上 1.05；
2. SOC 接近 0 时对称反向：`E[OCV] > OCV(μ)` → 预测电压偏高 → 新息为负 → 往下推 → 撞 −0.05；
3. **一旦撞在轨上，夹紧区间内的 `dOCV/dSOC` 是 0** —— 量测对 SOC 的雅可比消失，
   状态从「被推错」变成「推不动」，后续任何修正都进不来。

于是「偏离 → 夹紧 → 更大地偏离」，一路棘轮到量程尽头。EKF 只在 μ 处求导，
用的是真实斜率（越界时用端点斜率外推），**看不见 sigma 点的夹紧**，所以毫发无伤。

修法：**区间外按端点斜率线性外推**（`_linear_extrap`）。这既保持 C0 连续与单调，
也让 sigma 点的均值无偏。同一批工况、同一折参数、同一噪声种子下的 A/B：

| 工况 | 场景 | 夹紧（修复前） | 外推（修复后） | EKF |
|---|---|---|---|---|
| −20 °C NN | `known` | 58.97 | **2.19** | 3.52 |
| −20 °C NN | `init30` | 62.21 | **2.56** | 2.58 |
| −20 °C LA92 | `bias20ma` | 40.18 | **6.94** | 4.18 |
| 0 °C NN | `known` | 17.28 | **6.01** | 2.82 |

*全程 RMSE，pp。脚本 `scripts/07_ukf_clip_ab.py`，结果 `results/metrics/ukf_clip_ab.json`。*

改一行 `np.clip` 换来 **11–60 pp** 的改善（最差一条 17.28 → 6.01，最好一条 62.21 → 2.56）。
修复后 UKF 与 EKF 落在同一水平（有时更好，有时略差），
这才是可以放在同一张表里比较的状态。注意 `0 °C NN` 那条外推后仍是 6.01（EKF 2.82）——
说明**夹紧是主因但不是唯一原因**，剩下的是 §8.1 的 UT 残余偏差，只是量级已经从「不可用」降到「略差」。

### 8.3 小结

> UKF 的卖点是「不用求导」，代价是**对量测函数的全局形状敏感**。EKF 只关心 μ 处的斜率，
> 在 OCV 表这种「局部光滑、边界有硬约束」的函数上反而更稳。
> 要用 UKF，必须保证 `h` 在整个 sigma 支撑集上光滑且无夹紧——本项目为此专门改了 OCV 表的边界行为。

### 9.1 初值误差（其余为 0 A / 0 mV）

| 初值误差 | cc | EKF | UKF | AEKF |
|---|---|---|---|---|
| −40 pp | 36.12 | 3.28 | 3.53 | 1.97 |
| −30 pp | 28.09 | 3.53 | 3.95 | 2.45 |
| −20 pp | 19.40 | 3.13 | 4.35 | 1.70 |
| −10 pp | 9.99 | 2.37 | 4.15 | 1.55 |
| −5 pp | 4.99 | 2.62 | 4.33 | 1.80 |
| 0 pp | 0.01 | 3.78 | 4.07 | 1.27 |

**这张表是本报告最重要的一张。** 库仑计数严格线性（误差 = 初值误差），
三个滤波器**基本不动**（EKF 2.37–3.78、UKF 3.53–4.35、AEKF 1.27–2.45）。
初值差 40 pp 时，纯积分 36 pp，EKF 3.3 pp —— **差 11 倍**。
这就是「为什么值得上滤波器」的全部答案，也是 §7 里那张汇总表的另一种读法。

细看有个反直觉的点：**EKF 在 −10 pp 处（2.37）比 0 pp 处（3.78）还好**。
不是噪声，是这批工况的模型偏差方向为「估计偏高」，一个略微偏低的初值恰好把它抵掉了。
这类「误差互相抵消」是单点基准最容易被骗的地方，也是必须扫一条轴而不是只报一个数的原因。

### 9.2 电流偏置（其余为 0 pp / 0 mV）

| 电流偏置 | cc | EKF | UKF | AEKF |
|---|---|---|---|---|
| −50 mA | 2.63 | 7.05 | 8.47 | 2.00 |
| −20 mA | 1.05 | 5.45 | 5.83 | 1.14 |
| −10 mA | 0.52 | 4.53 | 4.91 | 1.10 |
| 0 | 0.01 | 3.78 | 4.07 | 1.27 |
| +10 mA | 0.53 | 3.27 | 3.82 | 1.35 |
| +20 mA | 1.06 | 2.93 | 4.26 | 1.68 |
| +50 mA | 2.64 | 3.46 | 5.12 | 3.11 |

三个结论：

1. **库仑计数对偏置是严格线性的、并且对称**（±10 mA → 0.52/0.53，±20 mA → 1.05/1.06，
   ±50 mA → 2.63/2.64），与 §7.3 的推导一致：漂移 = 偏置 × 时长 / 容量。
2. **EKF 是明显不对称的**：−50 mA 时 7.05 pp，+50 mA 时 3.46 pp。因为偏置的符号决定了
   「积分漂移」与「模型电压偏差」是同向还是反向叠加 —— 反向时互相抵消，同向时相加。
   **只报一个符号的偏置会低估 EKF 的最坏情况一倍。**
3. **拐点在 ±50 mA，不是 ±20 mA。** 20 mA（≈0.7% C）以内库仑计数（1.06）仍优于 EKF（2.93）；
   到 50 mA 时 cc 2.63 才与 EKF 3.46 持平。所以「小偏置下纯积分更好」这条结论的适用范围
   比想象中宽 —— **只要分流器偏置在 0.7% C 以内、且单次行程不超过 6 小时**。
4. **AEKF 在整条轴上都是最好的**（1.10–3.11），且对符号不敏感（2.00 / 3.11）。
   这正是它的设计目标：`R` 自适应把「模型不可信」这件事学出来。

### 9.3 电压噪声（其余为 0 pp / 0 A）

| 电压噪声 | cc | EKF | UKF | AEKF |
|---|---|---|---|---|
| 0 mV | 0.01 | 3.78 | 4.07 | 1.27 |
| 5 mV | – | 3.83 | 4.02 | 1.51 |
| 10 mV | – | 3.76 | 4.72 | 1.40 |
| 20 mV | – | 4.39 | 6.25 | 2.06 |
| 30 mV | – | 5.03 | 7.12 | 1.24 |

- **库仑计数与电压噪声无关**（0.01 不变）——它根本不看电压。这张表里它是「噪声免疫」的参照线。
- **EKF 只涨 33%**（3.78 → 5.03）：10 mV 的噪声对 `R = (10 mV)²` 本来就是匹配的，
  加噪声只是让增益略微失配。
- **UKF 涨 75%**（4.07 → 7.12），是三者中最敏感的。原因与 §8 同一个：噪声经 sigma 点
  进到 `S` 里，而 `S` 又被 UT 的均值偏差二次放大，等效于「噪声被算了两次」。
- **AEKF 在 30 mV 处反而回到 1.24**（比 0 mV 的 1.27 还好）。这不是噪声，是自适应在起作用：
  噪声大 → 新息协方差大 → `R` 被推高 → 滤波器更信积分、更少信电压 →
  在这批「模型电压有 50–100 mV 系统偏差」的数据上，**少信电压恰好是对的**。
  换句话说，**AEKF 把「噪声」当成了「模型不可信的信号」来用**，而两者在这批数据上确实同源。

### 9.4 三条轴合起来说什么

| 问题 | 答案 |
|---|---|
| 初值能错多少还能救？ | 40 pp 以内都能救回 3–4 pp 量级（cc 会到 36 pp） |
| 电流偏置多大还能忍？ | 20 mA 以内纯积分仍占优；50 mA 才与 EKF 持平 |
| 噪声把精度压多少？ | EKF +33%、UKF +75%、AEKF 基本不变 |
| 哪个估计器最稳？ | AEKF：三条轴上都是最低且最平 |

**注意这张表的边界**：只有 6 条工况、单一轴扫描（没有交互项）。
如果「40 pp 初值 + 50 mA 偏置」同时发生，误差不是两行相加 —— §7 的 `hard` 场景
（30 pp + 20 mA）已经说明它比两个单独场景都差。

## 10. 可复用模块

`src/bmsoc/` 的对外接口：

```python
from bmsoc.filters import EKF, UKF, AEKF, CoulombCounter, FilterConfig, ESTIMATORS, make
from bmsoc.ecm import RCParams
from bmsoc.profiles import DrivingProfile

est = EKF(ocv=ocv2d, params=RCParams(r0, r1, tau1, r2, tau2, dv=0.0),
          capacity_ah=2.6, cfg=FilterConfig(soc0=0.7, sigma_soc0=0.2))
out = est.run(profile, voltage_noise=0.01, seed=0, current_bias_a=0.02)
# out["soc_hat"], ["bias_hat"], ["sigma_soc"], ["innovation"], ["nis"], ["gain_soc"], ["volt_pred"]
```

约束与约定：

| 项 | 约定 |
|---|---|
| 电流符号 | **充电为正、放电为负** |
| 状态顺序 | `[soc, u1, u2, b]`，`b` 单位为 V |
| `ocv` 参数 | 需支持 `ocv(soc_array, temp_scalar)` 与 `docv(...)`；也接受一维 `OCVCurve`（自动降级） |
| 时间步长 | 由 `DrivingProfile.dt` 决定，任意正数（内部按 `Δt` 精确离散化） |
| 裁剪 | `soc_clip=(-0.05,1.05)`、`u_clip=0.6 V`、`b_clip=0.3 V`，可在 `FilterConfig` 里改 |

要在自己的数据上跑，只需要构造一个 `DrivingProfile`（`t_s/current_a/voltage_v/temp_c/soc_ref/capacity_ah`），
`bmsoc.profiles.build_profile()` 可以从原始序列直接生成。

## 11. 局限性（诚实声明）

1. **只验证了一款电芯。** Panasonic NCR18650PF（NCA，2.9 Ah 标称 / 2.77 Ah 实测）。
   CALCE A123（LFP，2.3 Ah）只做了数据勘察，没有跑完整流程——LFP 的 OCV 平台极平
   （`voltage_gap` 在中段可达数十 mV per 1e-3 SOC），SOC 估计是另一类问题，不能直接外推本报告的结论。
2. **静置才有 OCV 真值。** OCV 表来自 HPPC 长静置末电压；动态工况中电芯从未真正静置到平衡，
   所以 `dv` 在低温被顶到 −138 mV（0/24 折触及 −150 mV 边界，但方向一致、随温度单调），
   说明低温 OCV 表与动态工况的基准不自洽。真实 BMS 里这是「OCV 表的温度外推」问题，本项目没有解决。
3. **二阶 RC 结构在数小时尺度上不够。** `τ2` 在 24 折里 17 折顶到 6000 s 上界，
   慢支路退化成一个漂移项。需要三阶或分数阶模型才能把这个自由度用掉。
4. **容量衰减与内阻增长没有建模。** `Q_ref` 与 `R0` 是每个温度一个常数，
   相当于假设测试期内电芯不老化。这批数据是同一批新电芯的短期测试，所以问题不大，
   但真实车端必须耦合 SOH 估计（A2 的产物）。
5. **没有做电流偏置的在线辨识。** 本项目的偏置是「给定」的（场景设定），
   滤波器只能靠电压反馈去抵消它，不能估计它。把偏置也建成状态会有可辨识性问题
   （它与 SOC 在平台区同向）。
6. **`init30` 场景的收敛偏乐观。** 裁剪后保留了 300 s 静置，滤波器在这段恒压窗口里
   就能把初值拉回来（`converge5_median` 约 0–1 s）。若要求「起步瞬间就要准」，
   应把 `--keep-rest` 设为 0，误差会显著变大。
7. **AUX：数据质量依赖。** §2.3 的坑说明这套流水线对重采样实现对错极其敏感；
   `tests/test_profiles.py::test_resample_holds_value_across_sparse_gaps` 是为它加的回归测试。
